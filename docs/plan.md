# STARK 101 実装計画

FibonacciSqを題材に、Rustでトレースの生成からSTARK証明の検証までを段階的に実装します。全5段階を実装済みです。[実行手順と全体図](../README.md)

## ソースコードのコメント方針

公開する関数や型には、役割、入力と出力、呼び出し側が守る前提を日本語のRustdocコメント（`///`）で記述します。数学やプロトコルの理解に必要な箇所には、スライドの式とコード上の変数の対応、処理の理由、順序を守る理由を短いコメント（`//`）で説明します。

| 段階 | コメントで説明すること |
| --- | --- |
| トレース・LDE・Merkle木 | 二乗ごとに剰余を取る理由、`trace[i]` と `f(g^i)` の対応、拡張した評価領域に元の点を含めない理由 |
| 多項式制約 | 各分子・分母がどの制約を表すか、遷移が添字1020までで終わる理由 |
| FRI | `x` と `−x` から偶数次・奇数次の成分を取り出す式と、折り畳むと次数上限が下がる理由 |
| 証明と検証 | 何をハッシュに取り込んでからチャレンジを導くか、検証者が各開示値をどのrootと照合するか |
| 測定 | 証明サイズに含めるデータと、検証時間の計測範囲 |

各段階のレビューでは、該当するコメントを読んでスライドの式をコード上で追えることを確認します。数式や処理順を変更したときは、対応するコメントも同時に更新します。

## 各段階の実装内容と完了条件

### 1. トレースを多項式として固定する

実装済みの1,023項を、位数1,024の元 `g` を使い、点 `g^i`（i = 0〜1022）の値として並べます。これらを補間すると次数1,022以下の多項式 `f` が一意に決まります。次に、元の点と交わらない8,192点の乗法剰余類で同じ `f` を評価します。これが低次数拡張（LDE）です。評価値を葉とするMerkle木を作り、rootを公開します。

有限体演算、補間・評価、Merkle木の順で実装します。完了条件は、元の全点でトレースが復元できること、LDEの各葉に対する認証が通ること、葉を1つ変更すると元のrootに対するその葉の認証が失敗することです。[Part 1 · Statement, LDE and Commitment](https://starkware.co/wp-content/uploads/2021/12/STARK101-Part1.pdf)

### 2. 数列の規則を多項式の割り切れ方に変換する

初項の条件 `f(1) = 1` は、`f(X) − 1` が `X − 1` で割り切れることと同じです。末尾と漸化式にも同じ考え方を使います。

| 条件 | 分子 | 分母 |
| --- | --- | --- |
| 初項 | f(X) − 1 | X − 1 |
| 末尾 | f(X) − 2338775057 | X − g¹⁰²² |
| 遷移 | f(g²X) − f(gX)² − f(X)² | i = 0〜1020 の (X − gⁱ) の積 |

最後の遷移は第1,021項（添字1020）から末尾を見るので、分母の積もそこで止まります。トレースのrootを固定してから3つの係数を導き、各商に係数を掛けて足した合成多項式（CP）の評価表を固定します。正しいトレースでは各除算の余りがゼロで、CPの次数は最大1,023です。テストでは途中の1項だけを変更し、遷移制約の余りがゼロでなくなることも確かめます。[Part 2 · Polynomial Constraints](https://starkware.co/wp-content/uploads/2021/12/STARK101-Part2.pdf)

### 3. FRIで低次数性を検査する準備をする

多項式を偶数次と奇数次に分けると `P(X) = E(X²) + X O(X²)` と書けます。点 `x` と `−x` の値があれば、和と差から `E(x²)` と `O(x²)` を求められます。層のrootを固定してからチャレンジ値 β を導き、次の層の値を `E(x²) + β O(x²)` とします。各回で評価点の数が半分になり、次数の上限も半分（端数切り捨て）になります。

まず小さな既知の多項式で、係数から計算した次層と評価値のペアから作った次層が一致することをテストします。本実装ではCPとトレースの両方の次数を検査するため、初期層に `CP + γ₀·f + γ₁·X·f` を使います。次数上限1,023から10回折り畳むと、残る8点の値がすべて同じになります。[Part 3 · FRI Commitment](https://starkware.co/wp-content/uploads/2021/12/STARK101-Part3.pdf)

### 4. 証明を生成し、独立した検証者で読む

証明者は公開命題、各root、最終定数を決まった順でハッシュに取り込みます。各段階でそれまでの履歴から係数や問い合わせ位置を導く方法がFiat–Shamir変換です。証明には問い合わせへの応答として、トレースの3点 `f(x), f(gx), f(g²x)`、CPの開示値、FRI各層のペア、それぞれのMerkle認証経路を含めます。

検証者の入力は公開命題と証明です。検証者自身が同じ履歴からチャレンジを再現し、認証経路、3点から再計算したCP、折り畳み結果と次層の値、最後の定数まで順に照合します。完了条件は、証明を別プロセスで検証できること、公開した末尾・認証経路・最終定数を個別に変更したテストで拒否できることです。[Part 4 · The Proof](https://starkware.co/wp-content/uploads/2021/12/STARK101-Part4.pdf)

### 5. 証明の大きさを測る

同じ問い合わせ数でトレース長を変え、証明全体のバイト数、そのうち認証経路が占めるバイト数、検証時間を記録します。次にトレース長を固定し、問い合わせ数だけを変えます。どの条件で経路の長さが変わり、どの条件で経路の本数が変わるかを測定表から説明できれば完了です。[Finale · Review and Food for Thought](https://starkware.co/wp-content/uploads/2023/09/Stark-101-Finale.pdf)
